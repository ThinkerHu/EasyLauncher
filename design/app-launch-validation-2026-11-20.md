# 应用启动缩放转场（2026-11-20）

## 实现

- 桌面图标、Dock 常驻/最近使用图标、应用库与文件夹内图标，在点击时从当前 LayoutCoordinates 读取图标的窗口坐标。
- 将 Compose 窗口坐标转换为宿主 View 局部坐标，通过 ActivityOptions.makeScaleUpAnimation 交给窗口管理器执行真实应用窗口缩放。Intent.sourceBounds 同步携带图标屏幕区域；不截取其他应用画面。
- 快捷项启动也传入同一来源区域和动画参数。
- 窗口偏移包含 Dialog 场景；不使用按包名缓存的图标位置，避免同一应用在桌面、Dock、应用库同时出现时错用锚点。
- 无有效图标来源时使用系统淡入淡出；关闭动态效果时传入零动画资源。现有系统动画倍率保持不变。

- 录制的窗口转场中可见真实应用画面缩放，横屏打开设置和计算器均已检查。冷启动/已有任务的窗口转场由系统执行，应用可自行覆盖或追加内部转场。

## Home 返回缩回图标（追加验证）

- 进一步实机验证后，修正此前对退出动画的限制判断：远程动画接口需要特权，但当前华为 Android 10 固件接受默认桌面在 HOME onNewIntent/onResume 中调用公开的 Activity.overridePendingTransition，同时指定真实第三方应用窗口的退出动画。
- 最初使用 1500ms 固定中心缩放验证接口是否有效；该探针和日志代码已移除，正式动画为 380ms，末段渐隐，桌面在窗口下方直接显露。
- MainActivity 持有 HomeReturnAnimation，仅消费本次由桌面发起的应用启动记录，在应用启动与桌面 onPause/onStop 时准备落点，收到 HOME 后立即提交已准备的动画；BACK、普通恢复、解锁不会重新使用旧记录。
- 桌面图标、文件夹及 Dock 图标通过 DisposableEffect 注册、注销实时布局锚点。优先返回启动时的同一个可见图标；应用库、文件夹内启动则查找可见的桌面图标、包含它的文件夹，最后查找 Dock。找不到有效图标时保留系统转场。
- 应用启动成功后关闭应用库/文件夹覆盖层。HOME 返回应用时保留原桌面页，再次在桌面按 HOME 仍可返回第一页。
- XML 窗口动画在 system_server 中加载，不能传入任意运行时 pivot。构建时生成 51×51 个百分比落点资源，由实际图标中心选择最近落点；每个方向最大偏差为窗口尺寸的 1%（本机最大约 20px），落点仍位于实测图标区域内。并非 iOS 的连续圆角形变或跟随手指的手势动画。
- 生成资源仅在 build/generated 中；源码保留生成任务。生成的 Java 数组使用 R.anim 静态引用，避免 Release 资源压缩删掉动态选择的动画。已检查 Release APK，2601 个资源全部保留。
- 关闭动态效果或系统 Animator 时长倍率为 0 时，HOME 返回使用零动画。分屏、画中画、应用期间发生方向变化、无有效锚点时保留系统转场，避免错误落点。
- 该机制针对从 EasyLauncher 启动后直接按 HOME 的返回，不承诺判断应用内再次跳往另一个 App 后的真实最前台应用。未使用 Usage Access、无障碍或系统特权。
- Android 14 及之后对跨任务自定义转场有限制；本次验证结论限定当前 Huawei BAH3-W59 / Android 10，其他系统可由系统接管转场。

## Home 返回动效柔化（2026-11-20，第二次调整）

- 反馈：380ms 的窗口缩放一直收至 0，收尾像消失到一个点；桌面完全静止，缺少前后层次。
- 缩放改为 520ms 的临界阻尼弹簧响应：`1 - (1 + 6.5t) exp(-6.5t)`，按终点归一化，采样为原生 pathInterpolator。响应单调，避免缩小窗口反向翻转或负缩放。
- 缩放从屏幕中心执行，位移单独从屏幕中心归位到图标中心，两者使用不同的时间曲线。保留 51×51 落点网格及原有图标选择策略。
- 最终缩放保留 5.5%，在 320–490ms 淡出到图标上，避免缩成针尖；末段不会保留一个静止的小窗口。此终点尺寸是淡出阶段的视觉参数，尚非按图标轮廓进行裁切。
- 桌面原生入场由 103.5% 回落至 100%，历时 560ms，与应用退出由同一次系统转场调度。全程覆盖屏幕，避免小于 100% 缩放产生边缘黑底。
- 沿用提前计算与返回时新一帧绘制的时序处理，继续遵循减少动态效果设置；不更改系统动画倍率。
- 使用公开窗口动画完成真实应用窗口的缩放与平移。连续圆角变形、真实应用画面裁切成图标、跟随手指的交互式 Home 进度仍需要系统级窗口控制；本次不宣称与 iPhone 完全一致。
