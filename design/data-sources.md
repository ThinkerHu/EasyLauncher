# 云山桌面 · 数据来源与权限边界

原生桌面与 H5 原型的数据边界不同。H5 只提供本地演示；原生版本在设备上读取系统日历、调用天气服务，并可选托管其他应用公开的小组件。

| 内容 | 当前实现 | 授权 / 配置 | 缺省行为 |
| --- | --- | --- | --- |
| 天气 | 和风天气 Weather v1 + Geo v2；16 个常用城市与在线城市搜索；当前温度、体感、湿度、风速风向、24 小时 / 五日预报、日出日落与最高紫外线 | `INTERNET`；城市由用户选择，不请求定位 | 每个城市独立缓存；刷新保留已显示数据；失败明确提示缓存状态；无缓存显示错误和重试入口 |
| 日程 | `CalendarContract.Instances`，系统时区，当天最多 5 项 | 首次点击申请 `READ_CALENDAR` | 拒绝后显示连接入口；无事件显示今天暂无安排，并可打开系统日历 |
| 系统小组件 | `AppWidgetManager` + `AppWidgetHost`，支持 provider 绑定、配置、重启恢复与移除 | 绑定由系统确认；provider 自己负责数据权限 | provider 无法找到时显示不可用卡片，可在整理模式移除 |
| 音乐 | 暂未实现内置 MediaSession 卡片，可通过公开的小组件扩展 | 由音乐应用 provider 决定 | 不读取或记录第三方媒体数据 |

## 天气

`WeatherRepository` 使用账户专属 API Host，经 HTTPS 请求和风 Weather v1 实况、7 日预报（界面显示前 5 日）、24 小时预报与 Geo v2 城市搜索。坐标按接口要求保留两位小数，使用 `X-QW-Api-Key` 标头认证，支持 gzip 解压，不跟随重定向转发凭据。天气端点只发送所选城市坐标；在线城市搜索发送输入的城市名称；均不申请设备定位权限。

按当前 v1 数据结构解析嵌套 value/unit、ISO-8601 时间、0–1 湿度和降水概率。显示时将湿度和概率换算为百分比，m/s 风速换算为 km/h；使用所选城市时区显示日出日落及预报时间。缺失的可选字段显示“—”，不生成替代数据。天气图标映射和风天气现象代码，日夜由预报中的日出日落时间决定。

连接设置可从天气页右上角进入。API Host 和 Key 通过 Android Keystore 的 AES-GCM 密钥加密后存入应用 noBackupFilesDir，不存入项目源码、普通偏好设置或 Android 备份；Key 输入使用密码遮罩，退出配置页后清空输入状态。只允许和风官方 qweatherapi.com 及区域子域名，避免误将认证头发送到其他站点。凭据为空时显示连接入口，不请求网络。

`LauncherModel` 按城市保存和风快照，与此前 Open-Meteo 缓存使用不同键，避免切换数据源后错误归因。最近 6 个选择与城市时区保存在本机。桌面天气卡片使用原生 VerticalPager，上滑下一城市、下滑上一城市，右侧指示当前城市位置；城市列表保持固定顺序并保存，切换不重排。详情页新选城市自动加入列表，最多 6 个。手动刷新保留当前数据，切换城市取消旧请求并校验请求版本。前台每 30 分钟检查更新；已有半小时内的完整数据时不重复请求，后台不轮询。在线城市搜索有 450ms 防抖，可用本地常用城市作为离线选择入口。认证、订阅权限、额度和网络错误有对应提示；小时预报单独失败时仍显示实况和每日预报，并显示部分数据不可用提示。

天气画面以 Compose Canvas 绘制晴天、夜晚、多云、雨、雪、雾和雷雨，只更新绘制状态；逐小时和多日小图标保持静态。桌面被覆盖、应用非活动或启用“减少动态效果”时停止装饰动画。天气详情及卡片标注和风天气，详情页提供服务端返回的来源说明链接。

正式分发前仍需核对账号订阅、免费额度、服务许可和隐私说明。账户的 API Key 适合当前设备验证；公开分发需评估用户自行配置或服务端签发短期 JWT，避免共享开发者密钥。和风官方认证文档另公告自 2027-01-01 起限制 API Key 每日请求数量，应在正式发布计划中跟踪。

## 日历

通过 `CalendarContract.Instances.CONTENT_URI` 查询当天的事件实例，覆盖重复事件并使用系统时区。全天事件、空标题和跨天实例均安全处理；内容只在本机内存和 UI 中使用，不上传天气服务或其他无关服务。飞书、滴答清单等只有同步到系统日历后才会出现在此路径，不能承诺自动读取所有应用内部任务。

## 系统小组件

用户从 provider 列表中选择小组件，EasyLauncher 分配 `appWidgetId` 并调用 `bindAppWidgetIdIfAllowed`。需要授权时启动 `ACTION_APPWIDGET_BIND`，需要额外设置时启动 provider 的 `ACTION_APPWIDGET_CONFIGURE`；成功后保存 widgetId 与 provider ComponentName。Activity 生命周期调用 `startListening` / `stopListening`，Compose 通过 `AndroidView` 托管 `AppWidgetHostView`。

小组件的显示、刷新、网络访问和数据权限由原应用负责。provider 被卸载或权限失效时，桌面保留安全占位并允许移除，不尝试读取其私有数据库。

## 安全与隐私

只声明当前功能需要的 `INTERNET` 和 `READ_CALENDAR`。默认桌面设置必须经过系统 RoleManager / HOME 设置确认。正式版需要补充网络安全配置、隐私说明、日志脱敏、崩溃策略和服务端凭据管理。
